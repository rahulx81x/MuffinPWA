System Architecture & Engineering Spec

Deep-dive reference for software engineers and architects: trust boundaries, OAuth session model, serverless API contracts, client metrics engine, data residency, and extension points. Source of truth remains the repo — this page is the interactive companion to README §3.

Audience: Developer · Engineer · Architect

System Context

Muffin is a personal-finance Progressive Web App that treats a user’s Google Sheet as the system of record. A thin Netlify Functions BFF proxies the Sheets API so OAuth secrets never reach the browser; all KPI math runs client-side in a pure TypeScript module.

Architectural style

BFF + Spreadsheet-as-DB

Browser SPA → same-origin serverless functions → Google Sheets API. Per-user metadata (sheet link, Recipe, tour flag) lives in Netlify Blobs. No traditional app database for transactions.

Trust model

User-owned data plane

Each Google account authenticates itself; sheet access is scoped to that user’s linked workbook. Financial rows never leave Google’s sheet + the request path through your Netlify function.

Non-goals

Not a bank aggregator

  • No Plaid / open-banking feeds
  • No multi-tenant shared ledgers
  • No server-side metrics persistence
  • Planner rows are browser-local only
Key invariants

Contract the UI depends on

  • Three fixed sheet tabs: Income, Expense, Investment
  • Transaction type = tab membership (not a column)
  • PF rows are display-only carve-outs from net worth
  • Recipe balances seed opening liquid + initial investments

Why the proxy exists (design rationale) ▼
  • Browser only calls same-origin /.netlify/functions/* — no CORS to Google.
  • GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET stay in Netlify / local env.
  • Refresh tokens live in an encrypted httpOnly cookie, never in localStorage or JS bundles.
  • Sheet ID + Recipe + tour completion are keyed by Google sub in Blobs — portable across devices.
  • Read and write share one transactions surface so optimistic-UI refresh stays simple.

API Surface

All routes are same-origin Netlify Functions. Client wrappers live in src/api/client.ts and always send credentials: 'include'. Expand an endpoint for method, body, and error codes.

Auth bootstrap auth-start · auth-callback · auth-me · auth-logout ▼
EndpointMethodContract
/.netlify/functions/auth-start GET (redirect) Starts Google OAuth; browser navigates here via AUTH_START_URL.
/.netlify/functions/auth-callback GET Exchanges code → tokens; sets muffin_session; redirects to app with short error codes on failure.
/.netlify/functions/auth-me GET Returns AuthMeResponse or 401. Hydrates user, sheet link, recipe, showTour.
/.netlify/functions/auth-logout POST Clears session cookie.
/.netlify/functions/health GET Session health probe used by the SPA.

Sheet onboarding sheet-link · sheet-create · sheet-unlink ▼
  • POST sheet-link — body { spreadsheetId } (raw ID or Sheets URL). Validates access, persists to Blobs.
  • POST sheet-create — creates a workbook with the three required tabs / headers, then links it.
  • POST sheet-unlink — clears spreadsheetId on the user record (does not delete the Google Sheet).

Missing sheet yields client NeedsSheetError (code: 'needsSheet') so the SPA can show onboarding.

Transactions CRUD GET · POST · PUT · DELETE /transactions ▼

Implements the ledger. Auth via session; spreadsheet from Blobs; OAuth refresh → Sheets.

MethodBodyBehavior
GET — Reads all rows from three tabs → Transaction[]. Cache-Control: no-store.
POST { tabName, rowData } Appends a row on the named tab.
PUT { tabName, rowIndex, rowData, expectedRow?, rowId? } Updates row; optional optimistic concurrency via expectedRow.
DELETE { tabName, rowIndex, expectedRow?, rowId? } Deletes row; same optional guard. 
// SheetRowData keys match sheet headers
{
  Date: "2026-08-10",
  Category: "Groceries",
  Amount: 3500,
  Comment: "Supermarket",
  "Investment Type": "Mutual Fund"  // Investment tab only
}

Typical status codes: 401 unauthenticated · 400 missing tab / needsSheet · 404 missing row · 200/204 success.

Recipe & tour recipe · tour-complete ▼
  • GET /recipe · PUT /recipe with { recipe: { openingBalance, investments[] } } — persisted on Blobs user record; SPA also caches muffinRecipe in localStorage. Primary hydrate path is auth-me.recipe via hydrateRecipeConfig; the client saves with saveRecipe (PUT). There is no separate client getRecipe() helper.
  • POST /tour-complete — sets tourCompletedAt so returning users skip the first-run tour.
Client error taxonomy: AuthRequiredError (401 / unauthenticated) vs NeedsSheetError (needsSheet) vs generic Error with server message. Prefer branching on these in UI rather than string-matching messages.

Provident Fund carve-out src/domain/providentFund.ts ▼

An investment row is PF when investmentType or category matches pf / epf / ppf (exact) or contains “provident fund” (case-insensitive). Those rows:

  • Still appear in Ledger
  • Are excluded from net worth, liquid, investment totals, breakup pie, monthly investment, planner investment
  • Surface only as providentFundBalance on Home → More Details

Use isCountedInvestment anywhere you aggregate “real” investments.

Auth, Session & Security Model

Google OAuth 2.0 with offline access; refresh token sealed into a 30-day cookie. Click through the auth sequence, then review crypto and privacy constraints.

Step 1 / 6
Crypto

Session cookie seal

  • Cookie name: muffin_session
  • AES-256-GCM; key = SHA-256(SESSION_SECRET)
  • Payload: sub, profile fields, refreshToken, exp
  • TTL: 30 days; Secure flag when redirect URI is non-localhost
  • Impl: netlify/lib/session.ts
Hardening

Operational controls

  • Function responses: Cache-Control: no-store
  • Auth errors use short codes (clean address bar)
  • SPA strips leftover OAuth query params on load
  • .gitignore excludes .env (keeps .env.example)
  • SECRETS_SCAN_OMIT_KEYS=GOOGLE_REDIRECT_URI (public by design)
Threat notes for architects ▼
  • XSS → cookie theft: httpOnly mitigates JS reads; still treat XSS as critical because same-origin fetch with credentials works from injected scripts. CSP would be a natural next control.
  • SESSION_SECRET rotation: invalidates all sessions immediately — plan a coordinated redeploy.
  • Blobs keying: records keyed by Google sub; unlink sheet does not wipe Recipe unless you clear the record.
  • Local Blobs fallback: unlinked netlify dev writes to .netlify/muffin-users/ on disk — fine for solo dev, not a multi-machine store.
  • Limited Use: Privacy/Terms pages assert Google API Services User Data Policy Limited Use compliance.

Metrics Engine Lab

Live recreation of buildFinancialMetrics formulas. Adjust Recipe seeds and lifetime sums — PF is excluded from counted investment, exactly as in providentFund.ts.

Inputs

Canonical formulas investmentBalance = initialInvestments + Σ countedInvestment trackedLiquid = Σ income − Σ expense − Σ countedInvestment liquidBalance = openingBalance + trackedLiquid netWorth = investmentBalance + liquidBalance providentFund = Σ PF rows // NOT in netWorth growthSinceStart = netWorth − (initialInvestments + openingBalance)
Monthly KPIs & closing liquid buildMonthlyKPIs ▼

Groups by YYYY-MM. Per month: income, spends, counted investment, expense-by-category. Closing liquid rolls forward from Recipe opening balance: 

liquidSavings_m = income_m − spends_m − investment_m
closingLiquid_0 = openingBalance + liquidSavings_0
closingLiquid_m = closingLiquid_(m-1) + liquidSavings_m

Savings % helpers use income as the denominator (0 → 0%). PF never enters monthly investment.

Investment breakup buildInvestmentBreakup ▼
Seeds from Recipe getInitialInvestments(), then adds counted sheet rows keyed by investmentType || category || 'Uncategorized'. Home shows top 3; ChartModal pie shows full map. PF omitted entirely.

Mobile-first shell (max-w-lg). App.tsx is a thin shell wired to useAuthSession, useSheetTransactions, usePlannerStore, and useAppModals. Feature UI lives under src/features/*.

  • features/settings — HeaderMenu, Recipe, Tour, Guide, legal
  • components/ui — FloatingNav, SoftButton, ConfirmModal
  • shared/ — tabs, recipe sanitize, dates, Transaction DTO
  • Hooks: auth/sheet/planner/modals + theme, font, mask, recipe, PWA
Theme system src/lib/themes.ts ▼
Six variants (3 light / 3 dark): Classic, Blueberry, Pistachio Matcha, Double Chocolate, Red Velvet, Salted Caramel. Applied via data-theme + optional dark class; persisted as muffinTheme. Charts pull per-theme chartColors. Motion springs/variants centralized in src/lib/motion.ts. Favicon / PWA icon is a themed SVG from src/lib/muffinIcon.ts (not PNG assets).
Font system src/lib/fonts.ts · useFont ▼
Display/body font pairs (Muffin default, Josefin, Fredoka, Exo 2, Atkinson, Syne, Bricolage). Persisted as muffinFont; bootstrapped inline in index.html before paint, then owned by FontProvider / HeaderMenu.
PWA behavior vite.config.ts · VitePWA ▼
  • registerType: 'autoUpdate'
  • Workbox globPatterns: js,css,ico,png,svg,woff2 — index.html is excluded from precache
  • navigateFallback: undefined; document navigations use NetworkFirst so Edge Access / login challenges work
  • API routes (/.netlify/functions/*) are NetworkOnly
  • Shell assets may cache; live KPIs always need network → function → Sheets
  • Install: early beforeinstallprompt listener in index.html head & store in usePwaInstall; opens native 1-click prompt or falls back to interactive PwaInstallModal guide with Android/iOS/Desktop tabs
  • Manifest icons: SVG primary icon with PNG fallbacks for Desktop Chromium PWA installability + dynamic live theme SVG icon sync
Amount expression evaluator src/domain/evaluateAmount.ts ▼
SmartAmountInput wraps amount fields (Manage transaction + Planner) and can open AmountCalculatorModal. Accepts BODMAS arithmetic and % (e.g. 1000 * 18% → 180). Safe evaluator — not eval of arbitrary JS. Micro-haptics via navigator.vibrate(8) where supported. Client ID helper for planner rows: createId in src/domain/parseSheet.ts (sheet date parsing lives in netlify/functions/transactions.ts).
Recompute trigger: metrics rebuild when sheet transactions or Recipe config change. Planner overlays are view-local and never write to Sheets.

Extension playbook

Add a new KPI ▼
Extend FinancialMetrics / MetricKey → compute in metrics.ts → card in HomeView → optional ChartModal kind.
Add a sheet column ▼
Update row mapping in netlify/functions/transactions.ts, templates under templates/, and SheetRowData. Document header-row assumptions.
Swap the backend ▼
Keep src/api/client.ts shapes stable; replace the transactions function with any store that returns the same Transaction[] contract. Service-account auth is a viable alternative to per-user refresh tokens (share the sheet with the SA email).
PF-like display-only buckets ▼
Extend matching in providentFund.ts (or generalize it) and keep carve-outs out of isCountedInvestment consumers.
Known gaps (honest backlog): no automated tests/linters configured yet; functions are JS (TS migration would improve DX); CSP / rate limits are natural hardening next steps.
